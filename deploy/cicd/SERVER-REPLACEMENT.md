## 按顺序完成

1. 核对新机身份、系统、磁盘和 SSH 主机指纹。原实例与磁盘保留；在控制台准备快照，之后再导出并验证最新数据库备份。密码和私钥不发到聊天。
2. 在新机准备 Docker/Compose、主机 Nginx、持久化目录、资源限制和独立测试配置；预构建镜像后再启动候选。先做双前端、权限、History、发布/失败恢复及数据保留验收。
3. 准备 `kongqi.xyz` 的新主机 HTTPS 和可验证的 Let's Encrypt 自动续期；域名 DNS 暂不切换。新机可通过指定解析的 HTTPS 检查验收，不能关闭证书验证。DNS-01 的身份与 hook 准备见 [证书说明](TLS-RENEWAL.md)。
4. 展示明确的旧主机→新主机配置迁移计划并获得授权。仅将管理员、SMTP、极验、COS、CDN、百度统计的 15 个白名单变量写入新生产专用 root 0600 配置；数据库/Redis/JWT 独立生成。现有 `prepare_runtime.py` 默认只读取本机源文件，跨机传输入口仍需实现，不应把 `/etc/vueblog.env` 整份复制过去。
5. 新机镜像与配置就绪后，控制旧机写入并建立持久停写保护，防止重启或旧发布任务恢复旧数据库写入。导出最终 0002 归档、版本和冻结摘要，经加密 SSH 传输至新生产私有目录。
6. 新目标数据库必须为空；校验归档/摘要，事务导入后逐表比较，执行 0003 并再次比较旧业务字段。任何差异都阻止切流。跨主机停写、导入及恢复控制器仍需实现并演练。
7. 新机完整 HTTPS、真实管理员登录、文章/附件和统计验收通过后，更新主域名 A 记录。DNS 传播期间旧机应代理至经过证书校验的新站或进入明确的维护状态，不再写入旧库。
8. Flow 正式任务切换到新主机组，使用新 `current/deploy/scripts/flow_host.py` 和完整代码源 SHA；确认旧主机不再接受发布。随后通过实际 GitHub 提交→构建→Packages→新主机→飞书完成端到端验收。
9. 新生产备份/隔离恢复与定时任务通过、DNS 传播和旧流量观测完成后，再决定旧实例退役。[备份说明](BACKUP.md) 不能代替真实新生产恢复验收。

COS 桶、`cdn.kongqi.xyz` 的 CNAME/证书/鉴权、极验站点和百度统计 ID 可以保留；主站新 IP 切换不要求重建这些资源。实际凭据只在授权的生产配置迁移时使用，浏览器验收仍须核对真实服务，不能把已有旧版验收直接套到新版。
