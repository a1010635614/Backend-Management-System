# 腾讯云 CDN：私有 COS 图片与 PDF 下载

准备日期：2026-11-20。当前为接入准备：CDN 尚未开通，域名、CNAME、证书、云端鉴权与命中缓存均未验收。应用本地已增加 Type D 签名支持；云端与服务器配置完成后才能启用。

## 1. 开通服务

1. 使用现有 COS 所属账号登录 [CDN 控制台](https://console.cloud.tencent.com/cdn)。
   - 本次用户看到“下一代 CDN EdgeOne 3.0 欢迎您体验”，同时有“立即体验”和“继续开通 CDN”。这是体验推广入口；按当前项目方案选择“继续开通 CDN”。不能仅因出现 EdgeOne 名称就认定传统 CDN 已禁止开通。
2. 若提示实名认证，按页面要求完成。
3. 阅读开通协议与计费页。腾讯云当前说明默认按流量小时结算，HTTPS 请求另有计费；具体以账号页面为准。
4. 本项目准备使用普通 CDN 的静态加速及“中国境外”服务区域。先核对页面是否可用，再完成开通；无需为本步骤购买资源包。
5. 进入“域名管理”。如页面仅提供 EdgeOne 或提示账户限制，先核对产品差异，不能直接沿用本文 Type D 参数。

[官方开通指引](https://cloud.tencent.com/document/product/228/3149)、[基础计费](https://cloud.tencent.com/document/product/228/75562)、[计费项目说明](https://cloud.tencent.com/document/product/228/43799)。

## 2. 添加加速域名

| 字段 | 准备填写值 |
|---|---|
| 加速域名 | `cdn.kongqi.xyz` |
| 加速区域 | 中国境外 |
| 业务类型 | 静态加速／网页小文件（图片、PDF） |
| 源站类型 | 腾讯云 COS 源站 |
| 桶 | `kongqi-agent-1317119844` |
| 桶地域 | 上海 `ap-shanghai` |
| 源站访问形式 | 默认域名，不选静态网站端点 |
| 源站域名／回源 Host | `kongqi-agent-1317119844.cos.ap-shanghai.myqcloud.com` |
| 回源协议 | HTTPS |
| 私有桶访问／回源鉴权 | 开启；按页面授权 CDN 服务访问这个桶 |

操作顺序：添加域名 → 完成页面要求的域名归属验证 → 选择实际 COS 桶 → 授权 CDN 私有回源 → 保存。域名归属验证 TXT 与随后用于加速的 CNAME 是两种记录，按页面生成的实际值分别配置。

不修改桶的“私有读写”设置。现有应用 CAM 子账号继续仅用于上传和签名；CDN 的服务授权由控制台单独管理。

官方说明中国境外加速不要求 ICP 备案；中国境内或全球加速需要备案。该区域选择只影响本次 CDN，不代表主站的备案状态已经解决。上海源站到境外节点存在跨区域回源，接入后需实测响应时间。

[域名接入要求](https://intl.cloud.tencent.com/document/product/228/31476?lang=en)、[私有 COS 加速说明](https://intl.cloud.tencent.com/ind/document/product/436/18670)。

## 3. 配置访客 URL 鉴权

私有 COS 回源授权允许 CDN 读取桶；还需单独开启访客鉴权，防止 CDN 无签名公开访问对象。

进入该域名的“访问控制 → 鉴权配置”，使用以下固定协议：

| 参数 | 值 |
|---|---|
| 类型 | Type D |
| 密钥 | 控制台生成并保管的 6～40 位英文字母/数字；建议随机 32 位 |
| 签名参数 | `sign` |
| 时间戳参数 | `t` |
| 时间格式 | 十进制 Unix 时间戳 |
| 有效时长 | `300` 秒 |
| 鉴权对象 | 全部文件 |

密钥只填写到腾讯云和服务器配置中，不提交到 Git，不发送到聊天。它是 CDN 专用签名密钥，与 COS SecretKey、飞书签名密钥分别保管。

应用计算协议为 `MD5(密钥 + URL路径 + 生成时间戳)`，参数之间没有分隔符。时间戳是生成时间，不是生成时间加 300；到期判断由 CDN 的 300 秒配置完成。Type D 会从缓存键中移除相应鉴权参数，并仍在请求时执行鉴权。

[Type D 官方协议](https://cloud.tencent.cn/document/product/228/41625)。

## 4. 配置 HTTPS 和缓存

1. 在 CDN 域名的 HTTPS 配置中，为 `cdn.kongqi.xyz` 申请或选择匹配的证书；按页面做 DNS 验证。
2. 核对证书覆盖该子域名。主站 `kongqi.xyz` 的单域名证书不能直接视为覆盖此域名。
3. 开启 HTTPS，并按页面配置 HTTP 跳转 HTTPS。业务上传地址仍为 COS 签名 PUT。
4. 为 `/uploads/` 配置节点缓存，例如 1 天；这些对象使用随机、不可覆盖的文件路径。
5. 检查鉴权作用于缓存命中请求。签名参数变化不应产生额外对象缓存，但过期或错误签名应被拒绝。
6. 浏览器缓存采用不缓存或短缓存；明确区分“节点缓存 TTL”和“鉴权 300 秒”。要求严格拒绝浏览器复用旧响应时，浏览器端使用 `no-store`。
7. HTML、API、登录接口均继续访问主站，不加入这个资源 CDN。
8. 保存后等待控制台显示部署完成。

## 5. DNS CNAME

完成私有回源、访客鉴权和 HTTPS 后，再在 `kongqi.xyz` 的权威 DNS 服务中添加：

| 字段 | 值 |
|---|---|
| 类型 | CNAME |
| 主机记录 | `cdn` |
| 记录值 | 腾讯云为该加速域名实际分配的 CNAME，原样复制 |
| TTL | 默认值即可 |

不猜测 CNAME，不覆盖主站的 A 记录；若 `cdn` 已有同名记录，先检查冲突。随后验证公共 DNS 解析、HTTPS 主机名与证书链。

## 6. 应用配置与启用顺序

新增环境变量：

```dotenv
CDN_BASE_URL=https://cdn.kongqi.xyz
CDN_AUTH_KEY=仅在服务器填写控制台中同一份密钥
```

两项默认均为空：原有 COS 短时签名下载继续有效。填写两项后，公开文章的 `/api/media/{id}` 改为 307 跳转到 Type D CDN 链接；上传依旧签名直传 COS。配置只填一项或格式无效时，媒体接口返回 503，不生成无鉴权地址。

启用必须等以下前置验证通过：

1. 在隔离环境运行新增签名和接口检查。
2. 用现有云效链路发布包含 `app/cdn.py` 的新版本，配置暂时保持两项为空。
3. 在服务器端检查一份已公开图片与 PDF 的有效 CDN 签名下载，并比对 COS 原始字节。
4. 暖缓存后检查无签名、错误签名和已过期签名返回 403。
5. 先在项目根目录运行仅验证模式，在遮罩窗口输入 CDN 密钥：

   ```powershell
   .\backend\.venv\Scripts\python.exe .\deploy\configure_cdn.py
   ```

   工具使用已发布文章中体积较小的一份图片与一份 PDF，通过流式读取比较 COS/CDN 的 SHA-256、大小与类型，重复下载后检查无签名、错误签名、过期签名拒绝。只显示状态和有限缓存响应头；不会上传对象、创建文章或改配置。验证产生少量实际 CDN 下载用量，按服务计费。

6. 全部通过后，使用启用模式；密钥仍只在遮罩窗口输入：

   ```powershell
   .\backend\.venv\Scripts\python.exe .\deploy\configure_cdn.py --apply
   ```

   工具取得与原生发布相同的互斥锁，再做完整云端预检；通过后原子更新 `/etc/vueblog.env`，保留权限并重启应用。它会核对实际媒体跳转签名和应用健康，失败时恢复原环境内容并重新启动。若提示超时，先检查服务器，避免重复运行。不要手工 `source` 含密钥的环境文件。
7. 浏览器在正式网站打开图片、PDF，再核对 CDN 节点缓存命中证据。工具报告缓存响应头本身不保证所有节点命中。

## 7. 验收与回退

- 正式写作页图片与 PDF 上传成功，上传主机保持 COS。
- 公开文章媒体接口返回 CDN HTTPS 链接；未公开、未确认及已删除文章的附件不能从该接口获得新链接。
- 有效签名能下载，字节与 COS 一致；无签名、错误签名、过期签名被拒绝，包括已经命中 CDN 的资源。
- 连续访问查看腾讯云节点标识、缓存状态或 Age 等响应证据；不能把一次 200 当作命中证明。
- `/api/media` 的 307 仍为 `private, no-store`、`no-referrer`。
- 删除文章后，已经发出的 CDN URL 最多仍可在其签名有效期内使用；客户端保存的副本无法撤回。
- 回退时同时清空两个 CDN 配置并重启，恢复 COS 短时签名下载。确认媒体接口及业务恢复后，再按需停用 CDN 域名；缓存清理与域名停用须单独验证。

现有主站 HTTP-01 续期演练曾被公网 HTTP 403 拦截，后续可核对权威 DNS 服务后评估 DNS-01 自动续期。CDN 子域名证书与主站 Certbot 续期是两项独立配置，完成其中之一不能作为另一项完成的证据。
