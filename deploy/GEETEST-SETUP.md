# 极验 4.0 账号与 Web 场景准备

目标：在发送邮箱验证码前完成极验行为验证。2026-11-18 真实账号 ID/Key 已通过遮罩窗口安装，服务器健康与公开 ID 核对通过；用户随后确认极验通过、收到邮件并成功登录，当前本机预览与真实服务器后端的组合流程已验收。下方为可重复使用的准备与安装说明。

## 创建账号和产品

访问[极验官网](https://www.geetest.com/)，从官网注册入口创建账号并完成邮箱激活；个人项目按实际情况选择个人使用。官方文档中的[申请入口](https://www.geetest.com/Register)也可能展示预约或申请表单；如需人工开通，申请“行为验证第四代（CAPTCHA v4），Web 端，邮箱验证码登录场景”体验权限。以账号实际可开通的产品和套餐为准，不预设免费额度。

## 创建业务模块与场景

登录产品后台，选择“行为验”产品，进入业务管理。创建业务模块，再新增业务场景，建议填写：

| 字段 | 本项目建议值 |
|---|---|
| 应用名称 | Kongqi 博客 |
| 应用地址 | https://kongqi.xyz |
| 所属行业 | 按实际情况选择个人网站或相近类别 |
| 场景名称 | 邮箱验证码登录 |
| 客户端类型 | Web / H5（以页面选项为准） |
| 业务类型 | 登录；若有邮箱验证码场景可选择该项 |

官方说明应用地址属于备注信息。填写域名不表示网站备案或公网发布验收已完成，本项目仍按当前约定进行私有开发联调。

## 保存接入信息

场景创建后，找到对应的 captcha_id（验证 ID）和 captcha_key（验证 Key），将两项配对保管。官方指引允许在“部署检测”中选择“跳过指引”，进入后续配置；这不代表项目真实部署检测已经通过。

不要把 Key 发到聊天、截图或 GitHub，也不要填入前端代码。账号准备好后回复“极验 ID 和 Key 已准备好”，后续通过本机遮罩窗口配置服务器。

## 安装到当前服务器

账号准备好后，在项目根目录运行下面的工具，或由当前协作会话启动：

```powershell
.\backend\.venv\Scripts\python.exe .\deploy\configure_geetest.py
```

工具先核对既有 SSH 主机和密钥连接，再打开 Blog GeeTest configuration 遮罩窗口。输入同一 Web 场景的 captcha_id 和 captcha_key，两项均按官方定义检查 32 位长度；凭据仅通过 SSH 标准输入传输，不保存到本机日志。

服务器只更新 GEETEST_ID、GEETEST_KEY，保留数据库、JWT、SMTP 和 COS 配置。更新后重启服务并核对数据库健康和公开的 captcha ID；写入、重启或检查失败时恢复原环境文件并重启服务。中断或超时后先检查服务器状态，不盲目重复安装。

这些检查不能证明 Key 与 ID 有效配对。必须在下方真实浏览器流程通过后，才能认定极验配置有效；尚未创建账号时不要运行安装，也不要使用公开示例凭据。

## 接入验收

账号准备后再安装配置并检查登录页。用户在本机预览完成行为验证、请求邮件验证码、实际收信并登录；同时验证缺少或无效的行为验证结果会被服务端拒绝。只有真实流程通过后才记录极验接入完成。

参考：[官方接入指南](https://docs.geetest.com/gt4/handbook/)、[业务场景说明](https://docs.geetest.com/gt4/features/scene)、[快速集成指南](https://docs.geetest.com/gt4/quick_integration_guide)。
